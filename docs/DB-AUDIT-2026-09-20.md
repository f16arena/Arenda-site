## Осталось — требует отдельной работы

**Высокий приоритет**
1. **Права ролей общие на платформу** (`role_permissions` без `organization_id`). Сейчас закрыто
   запретом: встроенные роли меняет только владелец платформы. Правильно — колонка организации
   и уникальность `(organization_id, role, section)`.
2. **Деньги хранятся как число с плавающей точкой** (`Float`) во всех финансовых полях. В коде уже
   есть ручное округление `round2()` — признак того, что копейки «плывут». Нужен тип `Decimal(14,2)`
   и сквозная правка финансового кода.
3. **19 таблиц не привязаны к организации** (документы, подписи, черновики, проекты конструктора,
   сессии, логи). При удалении организации останутся «висеть»; запрос «аудит по моей организации»
   не отвечается.
4. **Организацию и здание нельзя удалить**: каскад обрывается на этажах, помещениях, счётчиках,
   расходах. Либо каскады, либо явное «удаляем только мягко».

**Средний**
5. Нет уникальности номеров: договоры, документы, этажи, помещения, счётчики, показания. Плюс две
   параллельные схемы нумерации (`Organization.docNumberStart` и счётчики на здании) — обе без атомарности.
6. Файлы лежат в самой базе (`stored_files.data`, `generated_documents.file_bytes`,
   `document_templates.file_bytes`, `site_images.data`). У шаблонов нет ни ограничения размера, ни
   учёта в квоте, ни мягкого удаления. Правильно — объектное хранилище, в базе только ключ и хэш.
7. Даты без часового пояса (`timestamp`), а бизнес идёт по Алматы — границы «до какого числа» плывут.
8. Все перечисления — просто строки; значения только в комментариях.
9. Три системы миграций (`prisma/migrations`, `migrations/*.sql` вручную, `prisma/manual-migrations`) —
   отсюда и расхождение из пункта про двойное начисление. Свести к одной.

**Низкий**
10. JSON то в `Json`, то строкой; разбор через `JSON.parse` в try/catch без проверки схемы.
11. Нет `updatedAt` у начислений, оплат, договоров, зданий, этажей, помещений.
12. Легаси-поля: `BuildingDecor.onRoof`, `PaymentReport.receiptDataUrl`, `TenantDocument.fileUrl`.
13. 18 пустых таблиц: лиды (раздел удалён), счётчики, задачи, рассрочки, расходы, жалобы, API-ключи.

## Эксплуатация

  настроить ежедневный дамп в отдельное хранилище.

## Требует решения владельца

1. **Резервные копии.** Нужен либо платный тариф Supabase (копии и восстановление на момент
   времени), либо внешнее хранилище для ночного дампа (ключи доступа).
2. **Файлы в базе.** Перенос в объектное хранилище (Supabase Storage) — нужен ключ
   `SUPABASE_SERVICE_ROLE_KEY` в переменных Vercel. Сейчас файлы занимают 5 МБ из 40 МБ базы;
   при росте это удорожает копии и замедляет запросы.
3. **Точный денежный тип (Decimal).** Полный перевод затрагивает более 1000 мест в расчётах;
   сейчас риск снят округлением в одном месте и проверками в базе. Делать отдельным заходом
   с проверкой всех сумм до и после.
4. **Три системы миграций.** Свести к `prisma/migrations` (старые ручные SQL-файлы уже
   применены и выполняются повторно вхолостую).
