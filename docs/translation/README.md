# Перевод документов на казахский: как это устроено

Файлы в этой папке собираются скриптом и отдаются юристу-переводчику.
Пересобрать после любой правки текста договора:

```
npx tsx scripts/export-contract-for-translation.ts
```

## Что отдавать переводчику

Семь файлов, каждый — обычный документ, который читается как документ:

| Файл | Что внутри |
|---|---|
| `1. Договор аренды помещения.docx` | 68 пунктов + приложение «Варианты пунктов» |
| `2. Договор аренды места на территории.docx` | 60 пунктов |
| `3. Договор о размещении оборудования.docx` | 59 пунктов |
| `4. Счёт на оплату.docx` | бланк счёта |
| `5. АВР (акт выполненных работ).docx` | форма Р-1 |
| `6. Акт сверки.docx` | бланк акта сверки |
| `7. Дополнительные соглашения.docx` | 35 формулировок: продление, расторжение, изменение условий, услуги |

Вместо подставляемых значений стоят прочерки — как в бумажном бланке. Никаких
таблиц и служебных пометок переводчик не видит.

`clause-map.json` — служебный, **переводчику не отдавать**: по нему перевод
раскладывается обратно по пунктам.

## Почему договор рендерится «на максимум»

Договор не хранится файлом — он собирается из пунктов, и часть из них
включается по условиям («как есть», входящий долг, ступени аренды, услуги,
коммунальные по счётчику или в составе платы). Возьми обычный подписанный
договор — в нём будет только сработавшая ветка, примерно половина пунктов.
Переведи его, и остальные однажды выйдут по-русски посреди казахского текста.

Поэтому каждый тип рендерится с включёнными опциями, а взаимоисключающие
формулировки уходят в приложение «Варианты пунктов». В конце скрипт
**проверяет покрытие**: сверяет собранные пункты со списком объявленных в коде.
Эта проверка уже нашла две дыры — пункт про каждый коммунальный ресурс
(в документ попадало только электричество) и взаимоисключающую пару «входит в
плату» / «оплачивается отдельно».

**Если скрипт пишет «ВНИМАНИЕ: не попали» — файлы переводчику не отдавать.**
Сначала включить недостающие условия в `maximalState` или добавить вариант
редакции рядом с `utilitiesIncluded`.

## Прочерки вместо подстановок

Договор рендерится с заведомо неповторяющимися образцовыми значениями (сумма
1 234 567, площадь 137 и т. д.), а потом они меняются на прочерки. Поэтому
значения в `SAMPLE` нельзя делать «круглыми»: 100 000 встретилось бы внутри
других чисел и затёрло бы их.

Проверка после генерации: в готовых файлах не должно остаться ни одного
образцового значения — ни «Образец», ни адреса, ни имён.

## Чего в файлах нет

- **Договор аренды места на крыше/фасаде.** Тип есть в списке, но своего текста
  у него нет — программа подставляет договор аренды помещения. Русский текст
  нужно составить отдельно, и только потом переводить.
- **Суммы прописью и склонение фамилий.** «Два миллиона пятьсот тысяч тенге»,
  «в лице директора Иванова И.И.» — это строит код (`lib/contract-engine/numerals.ts`,
  `lib/declension.ts`), в казахском правила свои. От переводчика нужны только
  образцы, модули пишутся отдельно.
- **ЭСФ.** Уходит на портал КГД в его формате, язык там не наш.

## Что делать с ответом переводчика

Вернуть надо те же файлы, целиком по-казахски, с сохранённым порядком пунктов.
Раскладываются они обратно по `clause-map.json`: там для каждого типа договора
лежит список пунктов в том же порядке, с идентификаторами. Номера пунктов
программа проставляет сама, поэтому нумерация не поедет.

**Порядок пунктов менять нельзя** — по нему идёт сопоставление.

## Правовое основание

Статья 15 Закона РК «О языках»: сделки физических и юридических лиц в
письменной форме излагаются **на государственном и русском** языках. То есть
нужен не «казахский вместо русского», а оба сразу — документ выпускается в две
колонки одним файлом, с одной подписью ЭЦП.

Отдельно попросить у юриста формулировку пункта о преимущественной редакции:
какая языковая версия применяется при расхождении.
