# Перевод документов на казахский: как это устроено

Файлы в этой папке собираются скриптом и отдаются юристу-переводчику.
Пересобрать после любой правки текста договора:

```
npx tsx scripts/export-contract-for-translation.ts
```

## Что отдавать переводчику

| Файл | Что внутри |
|---|---|
| `Договор — текст для перевода.docx` | 138 пунктов договора: аренда помещения, аренда места на территории, размещение оборудования |
| `Остальные документы — текст для перевода.docx` | 285 строк: допсоглашение, счёт на оплату, АВР, акт сверки, акт приёма-передачи |

Оба файла — таблицы с пустым столбцом «Қазақша». Переводчик заполняет его,
ничего больше не меняя.

## Почему не отдаём готовый договор

Договор не хранится файлом — он собирается из пунктов, и часть из них
включается по условиям («как есть», входящий долг, ступени аренды, услуги,
коммунальные по счётчику или в составе платы). В одном отрендеренном образце
видна только сработавшая ветка: переведи его — и реальный договор однажды
выйдет наполовину русским.

Поэтому скрипт выкручивает состояние «на максимум» по каждому типу договора и
объединяет результаты. В конце он **проверяет покрытие**: сверяет собранные
пункты со списком объявленных в коде и ругается, если какой-то не сработал ни
разу. Эта проверка уже нашла две дыры — пункт про каждый коммунальный ресурс
(в образец попадало только электричество) и взаимоисключающую пару «входит в
плату» / «оплачивается отдельно».

**Если скрипт пишет «ВНИМАНИЕ: не сработали» — файл переводчику не отдавать.**
Сначала добавить недостающие условия в `maximalState` или новый вариант в
`variants`.

## Пометки вида `{{АРЕНДНАЯ_ПЛАТА}}`

Это места, куда программа подставляет данные конкретного договора. Переводчик
обязан перенести их в казахский текст без изменений; переставлять внутри фразы
можно и нужно — в казахском другой порядок слов.

Скрипт получает их так: договор рендерится с заведомо неповторяющимися
образцовыми значениями (сумма 1 234 567, площадь 137 и т. д.), а потом они
меняются на пометки. Поэтому образцовые значения в `SAMPLE` нельзя делать
«круглыми»: 100 000 встретилось бы внутри других чисел и затёрло бы их.

## Чего в файлах нет

- **Договор аренды места на крыше/фасаде.** Тип есть в списке, но своего текста
  у него нет — программа подставляет договор аренды помещения. Русский текст
  нужно составить отдельно, и только потом переводить.
- **Суммы прописью и склонение фамилий.** «Два миллиона пятьсот тысяч тенге»,
  «в лице директора Иванова И.И.» — это строит код (`lib/contract-engine/numerals.ts`,
  `lib/declension.ts`), в казахском правила свои. От переводчика нужны только
  образцы, модули пишутся отдельно.
- **ЭСФ.** Уходит на портал КГД в его формате, язык там не наш.

## Что делать с ответом переводчика

Вернуть надо тот же файл с заполненным третьим столбцом. Пункты договора
вставляются обратно **по идентификатору** (`cl_subject`, `cl_term` …), поэтому
ни порядок, ни нумерация не поедут: номера пунктов программа проставляет сама.

## Правовое основание

Статья 15 Закона РК «О языках»: сделки физических и юридических лиц в
письменной форме излагаются **на государственном и русском** языках. То есть
нужен не «казахский вместо русского», а оба сразу — документ выпускается в две
колонки одним файлом, с одной подписью ЭЦП.

Отдельно попросить у юриста формулировку пункта о преимущественной редакции:
какая языковая версия применяется при расхождении.
